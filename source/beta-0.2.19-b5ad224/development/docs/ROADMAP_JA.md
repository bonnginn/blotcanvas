# BlotCanvas 開発ロードマップ

この文書は今後の実装候補を整理するためのメモです。実装順や仕様は、実際のWestern blot画像を用いた評価結果に応じて変更します。

## 1. 定量化の本格化

- 元画像を用いたレーン方向のIntensity profile
- バンドピークとbaselineの指定
- ピーク面積の積分
- 矩形ROI法との比較検証
- ImageJなど既存手法との整合性検証
- 飽和、低シグナル、不適切な露光への警告
- 解析領域、背景補正、正規化方法、測定値のログ保存

## 2. 統計処理

- 独立反復データの集約
- 比較群と検定方法の選択
- エラーバー、個々のデータ点、サンプル数の表示
- 統計解析結果と条件の保存・再読み込み

## 3. メンブレン境界の自動取得

CL、Merge、明視野画像などからメンブレン境界の候補を推定します。境界の外側にある不要な撮影領域を作業表示から除外し、メンブレンを画面内で大きく扱えるようにします。

想定する効果：

- 水平補正を行いやすくする
- 切り出し枠を細かく操作しやすくする
- マーカー位置を指定しやすくする
- 定量ROIを配置しやすくする

## 4. 作業の自動化

候補となる処理：

- 水平補正
- メンブレン境界
- クロップ領域
- マーカーバンド位置
- レーン中心
- 定量ROIと背景ROI

自動化は任意機能とし、次の利用方法を選べる設計にします。

- 手動中心：自動提案を表示せず、最初から利用者が操作
- 自動提案を利用：候補を表示し、採用、修正、破棄を選択
- 工程ごとの設定：水平補正だけ使用する、ROI提案は使用しない、など個別にオン・オフ

選択した設定は端末内に保存し、信頼できない自動提案を毎回閉じる必要がないようにします。

自動提案を使用した場合も、推定結果と可能であれば判断根拠や信頼度を画面上で確認できるようにします。うまくいかない場合には各工程を完全に手動で修正できる状態を維持し、自動処理だけで解析結果やFigureを確定する設計にはしません。

## 5. プロジェクトフォルダへの直接保存

最初の画像が入っていたフォルダ、または利用者が指定した作業フォルダへ、Figure、グラフ、Source record、CSV、プロジェクトJSONを直接保存できる方式を検討します。

ブラウザでは画像を読み込んだだけでは元フォルダへの書き込み権限を取得できないため、次の設計を想定します。

- Chrome／Edgeでは、作業開始時または最初の保存時に保存先フォルダを一度選択
- 選択したフォルダの権限が有効な間は、個別ダウンロードを繰り返さず同じ場所へ保存
- 以前選んだ保存先を端末内で記憶し、ブラウザが要求する場合だけ権限を再確認
- 元画像、アプリ出力、プロジェクトJSONを混同しないよう、必要に応じてBlotCanvas用サブフォルダを作成
- File System Access APIに対応しないSafariなどでは、従来のダウンロード方式へ自動的にフォールバック
- 保存先を設定しない利用者は、従来どおりブラウザのダウンロード先を使用可能

元画像を上書きせず、既存ファイルと同名になる場合は確認または安全な連番を付けることを必須とします。
